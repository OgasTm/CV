Method note. This round adds to `IRSA 前期开发与公开数据集/llm_agent_datasets.md` (20 Nov 2026) and does not repeat items listed there. Checks made this session (2026-11-23):
- Hugging Face (HF) licences were read from the HF API `license:` tag or the dataset card.

## 1. Papers (2023–2026) evaluating LLMs on radiation protection, health physics, nuclear medicine, radiotherapy and radiology patient questions

### Takeaway
Every RP/NM/RT patient-question study found is small: 12 to 115 expert-picked questions, single-turn, graded by expert Likert ratings. None released a reusable, licensed question set beyond the paper. Exam-style studies show the same weak spots across models: the regulations/laws section and calculation questions. Those are the parts IRSA hands to the rule engine and the dose engine. The Mass General Brigham guardrailed prostate-RT chatbot trial (NCT07719062) is registered but **not yet recruiting and has no results**.

### Inferences
- The published RP/NM evidence base is thin, single-turn and uses expert-picked FAQs. Every study measures answer quality without engine grounding, so IRSA's design (numbers from the engine, LLM only verbalises) has no direct published comparator. That is itself a citable gap for the IRSA concept paper.
- The failures recur across studies: fabricated references (RAI study), omissions (JNMT 2023; RT study), reading level too high (JAMA Netw Open 2024; Radiology 2024), errors in both directions on pregnancy (Clinical Imaging), and weakness on regulations and calculations (Japanese RPS exam in the earlier round; radiation biology exam). Each can be turned directly into an IRSA-Bench rubric axis.
- NCT07719062 is the nearest real-world comparator. When results appear (primary completion estimated Feb 2027), its clinician transcript-review protocol is worth copying for IRSA's IAEA pilot.

### Gaps
- Full text was not read for the RAI chain-of-thought study (journal, year and n unknown) or the Spanish PET/CT study (n unknown).
- No study was found on LLMs and the US health-physics **RSO** or **ABHP** certification exams, or on **ABNM**-style nuclear-medicine physician exams (searches returned only the NMT 600-MCQ and Japanese studies already in the earlier notes).
- No published LLM evaluation was found specifically on **177Lu-DOTATATE patient** questions. The Lu-PSMA (Bilgin 2024) and professional-facing Koller 2025 studies are already catalogued.
- No released patient question set with an open licence was found for 131I or 177Lu.

## 2. Released QA / dialogue datasets in NM, radiology and radiation oncology, plus multilingual medical datasets for IAEA member-state languages

### Takeaway
No radiation-protection or NM-therapy patient QA dataset with an open licence exists on HF, GitHub or PhysioNet. Searches for radioiodine, radiation-oncology, nuclear-medicine and thyroid terms returned only infrastructure statistics or imaging data. The usable openly licensed items are adjacent:
- ROND (Apache-2.0) for RO professional QA.
- Cancer-Myth (CC BY 4.0) for false-presupposition patient questions.

Radiology lay-language report datasets (LaymanRRG/BioLaySumm) derive from MIMIC-CXR and have no licence tag on HF. Treat them as bound by PhysioNet terms.

### Inferences
- For multilingual IRSA-Bench, there is no shortcut: radiation-protection items must be written in English and professionally translated, or written natively, for each target language. The open multilingual sets above are only useful to (a) screen candidate LLMs' medical register per language and (b) calibrate multilingual judges. MedExpQA (CC BY 4.0) and GerMedIQ (CC BY 4.0, with human vs LLM-judge labels) are the most directly useful.
- Cancer-Myth (CC BY 4.0) is the best openly licensed template for IRSA's "false reassurance / false premise" items. Its NFP control set shows how to measure the cost of over-correcting, which matters because IRSA must also not invent restrictions.

### Gaps
- No openly licensed **NM/RT patient** dialogue dataset in any language was found. HF searches for "radioiodine", "radiation oncology" and "nuclear medicine" returned no QA data (only WHO/OWID infrastructure statistics and RT-planning optimisation sets).
- Licences for RadLIT-9, the 2023 TXIT GitHub supplement and the original IgakuQA repository were not checked.
- Licence tags were read from the HF API. For most multilingual sets, the card text, the underlying source licences and the provenance were not checked one by one.

## 3. Patient / user simulators for evaluating health agents (2025–2026), with code, licence, and validation against real users

### Takeaway
Two medical simulators have released code: **PatientSim** (NeurIPS 2025 D&B; persona axes for personality, language proficiency, recall and confusion) and **DischargeBench** (persona-grounded discharge education). Both take their clinical profiles from **MIMIC** under PhysioNet credentialed licences, and PatientSim's code repo has **no LICENSE file**. Studies that compare simulators with real humans (2026) agree that LLM simulators are too cooperative, too uniform and front-load information, which inflates agent scores. IRSA-Bench therefore needs a human-calibration subset.

### Inferences
- Recommended IRSA simulator design: (1) a sampled **household fact sheet** (atomic facts; from the earlier round); (2) PatientSim-style persona axes, re-implemented because the code has no licence, mapped to health literacy, recall, anxiety/distrust and language proficiency; (3) DischargeBench-style metrics (topic checklist = must-say items; simulated comprehension = teach-back; claim-level safety audit = numeric/claim verifier).
- Simulators lean too cooperative (Sim2Real) and collapse toward the average patient. IRSA should therefore (a) add scripted frictions (withholding, contradicting, "I already asked the nurse"), (b) report human-calibrated scores on a pilot subset of real caregiver or standardised-patient dialogues, and (c) report results per language and dialect (Lost in Simulation).

### Gaps
- No simulator validated specifically for radiation-safety, caregiver or household-exposure conversations was found.
- Code licences for DischargeBench and the JMIR AI framework were not found. The *realsim* 1K dialogue licence was not checked.
- "MedSim" as a named 2025–2026 medical simulator was not found in searches. **UNVERIFIED** (possibly a generic name).

- **HealthBench Professional** (Apr 2026, MIT data): 525 physician-authored tasks, rubrics adjudicated by 3 or more physicians, about one-third red-teaming. OpenAI did not release an official grader, and an independent review rates it "Flawed".

### Inferences
- Proposed IRSA-Bench rubric pipeline from these methods:
  1. Draft item rubrics automatically from guideline or rule-engine atomic facts (2601.15161).
  2. Write criteria as Boolean checks (2503.23339).
  3. Keep a rubric only if it separates expert-preferred from rejected answers (2604.24710).
  4. Adjudicate in 3 phases with ≥3 experts (HealthBench Professional).
  5. Report judge–expert agreement, never only judge–judge consensus (2610.13303).
- For false reassurance, combine Cancer-Myth-style false-premise items with The Patient Is Always Right-style graded beliefs, keyed to the dose-engine output (e.g., the patient claims 1 day when the engine says 7 days), plus an NFP-style control set to catch over-restriction.

- The total physician count and per-specialty breakdown for HealthBench Professional were not found. The 525-task figure comes from a search summary of the OpenAI PDF, not a direct read.
- No openly licensed **radiation-specific** sycophancy or false-reassurance set exists.
- Code and data availability for 2604.24710, 2601.15161 and PhysAssistBench were not checked.

A jurisdiction profile for Canada should therefore call the dose engine's caregiver-dose computation rather than a lookup table. That is a useful contrast case for IRSA-Bench "jurisdiction switching".
